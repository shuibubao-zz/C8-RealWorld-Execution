# 系统架构文档 · WeChat Group as Class Management Agent Skill

> 依据：资料包《C8 WeChat Class Management Challenge》p.1–11 的三层架构与 Domain Model First 要求。
> 本文件描述**实际实现的架构**，未实现的组件在 §7 明确列出。

---

## 1. 三层架构（任务书 p.1–2）

```
┌─────────────────────────────────────────────────────────────────┐
│ Layer 3 · CLASS MANAGEMENT SKILLS (Skill Domain)                │
│  wechat-bridge | msg-classifier | submission-tracker | qa-sink   │
│  student-profile | class-report   （6 个子技能 + 1 个根 SKILL.md）│
│  watcher / alert_engine / report_engine / dashboard (L4 闭环)    │
├─────────────────────────────────────────────────────────────────┤
│ Layer 2 · COGNITIVE (规则分类与信号提取，可插拔)                  │
│  classifier(7 意图) → challenge_linker → submission_detector     │
│                    → qa_extractor → graph_store / nl_query       │
├─────────────────────────────────────────────────────────────────┤
│ Layer 1 · WECHAT CHANNEL ADAPTER (Transport)                    │
│  wechat_bridge.py：synthetic | jsonl | chatlog 三种显式 source   │
│  输出：7 字段 JSON Lines（msg_id/timestamp/sender/type/content/  │
│        media_ref/reply_to）                                       │
└─────────────────────────────────────────────────────────────────┘
```

**关键约束**：L2–L4 只认 L1 的 7 字段契约，不感知数据从哪来。换真实数据源只需换 adapter；换一门课只需改 `config/`。

## 2. 领域模型（Domain Model First，任务书 p.2–3）

**节点类型**（`schemas/domain-graph.yaml`）

| 节点 | 关键属性 | 本次实测数量 |
|---|---|---|
| Student | wechat_id / nickname / skill_tags / message_count / question_count / answer_count / submission_count | 22 |
| Challenge | id / name_cn / due_date / levels | 8 |
| Submission | timestamp / files / level_claimed / status / complete / missing_items | 8 |
| Message | timestamp / content / type / wechat_msg_id / intent / challenge_ref | 150 |
| QAPair | question / answer / topic_tags / quality_score | 14 |
| Report | type / generated_at / data_snapshot | 0（周报以 Markdown 文件形式落盘，未入图） |

**边类型**

| 边 | 语义 | 实测条数 |
|---|---|---|
| SENT | Student/Mentor → Message | 150 |
| TAGGED_WITH | Message → Challenge | 75 |
| SUBMITTED | Student → Submission；Submission → Challenge | 16 |
| PROGRESSED_TO | Student → Challenge（level=received） | 8 |
| ASKED / ANSWERED | Student/Mentor → QAPair | 14 / 14 |
| MENTORED | 回答者 → 提问者（由 reply_to 推断） | 14 |

合计 **203 节点 / 291 边**。`Report` 节点为 0 是如实记录：周报由 `report_engine.py` 直接输出 Markdown，没有回写图，这是本次的简化点。

**导师建模决策**：导师不是 `Student` 节点，使用 `Mentor:` 主体字符串。这样「学生数」不会被老师污染（W2 AAR 记录了这个修正）。

## 3. 数据流（端到端）

```
gen_fixture.py ──> data/synthetic_messages.jsonl (150 条, seed 20261114)
      │
wechat_bridge.py ──> evidence/sample_output.jsonl + .meta.json
      │
classifier.py ──> classified.jsonl (7 类意图 + confidence + reason)
      ├──> challenge_linker.py ──> challenge_refs.json
      ├──> submission_detector.py ──> submissions.json (矩阵/missing/alerts)
      └──> qa_extractor.py ──> qa_pairs.json
      │
graph_store.py ──> graph.json (Property Graph + 学生画像)
      ├──> nl_query.py ──> nl_query_answers.md / .json (6 类查询)
      ├──> alert_engine.py ──> alerts.json (4 类触发, 14 条)
      ├──> watcher.py ──> watcher_result.json + state/checkpoint.json
      └──> report_engine.py ──> weekly_report.md + dashboard_data.json
                                 + dashboard/dashboard_data.js
                                        │
                              dashboard/index.html (离线 8 维度)
```

`run_pipeline.py` 用 **subprocess 逐个调用上述 CLI**（不是 import 串起来），因此「模块可独立运行」是被真实执行验证过的：11 个步骤全部 `exit=0`。

## 4. 接口契约

**消息**（`schemas/message.schema.json`，`additionalProperties: false`）

```json
{
  "msg_id": "m0001",
  "timestamp": "2026-11-02T09:01:00+08:00",
  "sender": {"wechat_id": "s01", "nickname": "学生01"},
  "type": "text|image|file|voice|link|system",
  "content": "消息文本",
  "media_ref": null,
  "reply_to": null
}
```

**Skill IO**（每个 `SKILL.md` 都写明输入/输出/依赖/触发词）

| Skill | 输入 | 输出 |
|---|---|---|
| wechat-bridge | group, days, source | messages.jsonl |
| msg-classifier | messages.jsonl | classified.jsonl |
| submission-tracker | classified + refs | submissions.json |
| qa-sink | classified | qa_pairs.json |
| student-profile | graph + wechat_id | profile JSON |
| class-report | graph + submissions + qa | weekly_report.md + dashboard_data.json |

## 5. 关键设计决策（ADR）

| # | 决策 | 备选 | 理由 |
|---|---|---|---|
| ADR-1 | 标准库 dict + JSON 实现 Property Graph | Neo4j / NetworkX / SQLite+FTS5 | 零依赖、可复跑；任务书允许「快速原型」档位；牺牲图查询语言换取换机器即用 |
| ADR-2 | `*.yaml` 用 JSON 语法 | 原生 YAML + PyYAML | 满足目录规范，同时避开 C4A v4 踩过的「无 PyYAML 时 mini-YAML 行内注释崩溃」 |
| ADR-3 | 3 种显式数据源，真实源失败即报错 | 单一 wechat-cli / 静默兜底合成数据 | 隐私边界清晰，杜绝「假数据被当成真结果」 |
| ADR-4 | 规则引擎分类（预留 LLM 接口位但不实现） | LLM API 分类 | 无 API 预算、要求可审计可复现；不假装调用过 LLM |
| ADR-5 | 静态 HTML + `dashboard_data.js` 注入 | 在线服务 / CDN / 构建工具 | 双击即可离线查看，规避 `file://` fetch 跨域 |
| ADR-6 | 验收矩阵由代码现算 | 手写自评表 | 每个数字可追到文件，rubric「有验收记录」可复核 |

## 6. 预警规则（L4 Alert Engine）

| 规则 | 判定 | 本次触发 |
|---|---|---|
| deadline_warning | 距 deadline ≤3 天仍有未提交学生 | 1（模拟 as-of 2026-11-18） |
| silent_student | 最近 3 天零发言且此前有发言 | 0（如实记录） |
| low_submission_rate | 挑战提交率 <30% | 8 |
| activity_drop | 后半窗发言量较前半窗下降 >50%（KSTAR ΔE） | 1 |
| missing_attachment | 提交缺 AI 日志 | 4 |

## 7. 已知限制（未实现 / 未实测）

1. 未接入真实微信数据源（无授权）；L1「≥100 条真实消息」与 L4「≥1 周真实运行」未满足。
2. 未安装 OpenClaw / Claude Code，Skill **未被 Agent Runtime 实际识别调用**；只提供标准 `SKILL.md` 与 CLI。
3. 未实现 `on_message` / `on_schedule` / `on_query` hook 注册（需要 runtime 支持）；NL 查询以 CLI 形式提供。
4. 未实现双向通道（Wechaty 写回群）、群发提醒、公告确认。
5. 未接入 GitHub；`Report` 节点未回写图；周报未自动转公众号文章。
6. 预警的 `as-of` 为模拟时间点；分类器准确率非真实标注集证据。

详见 `../evidence/验收记录.md`。
